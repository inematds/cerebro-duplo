Um cérebro, dois agentes

O que é

O mesmo cérebro, sem virar dois

Seu segundo cérebro (a pasta de Markdown do kit astra-2cerebro) pode ser lido pelo Claude Code e pelo Codex. Cada um entra por uma porta diferente: CLAUDE.md e .claude/skills num lado, AGENTS.md e .agents/skills no outro. O cerebro-duplo mantém as portas iguais e decide qual usar.

🪞 Paridade

duplo.sh verificar confere que AGENTS.md = CLAUDE.md, que cada skill está espelhada byte a byte e que cada uma tem o openai.yaml do Codex. sync conserta. A skill duplo-verificar relata e propõe, sem mexer sozinha.

🧭 Roteamento

A skill qual-agente lê o pedido, escolhe agente + modelo + esforço com uma tabela (MCP configurado, repo aberto, raciocínio pesado, rotina barata) e devolve o comando. Perfis .env guardam modelo e esforço por tipo de tarefa.

📒 Uso e cota

uso registrar anota cada sessão em registro-uso.md; uso resumo soma por agente e perfil. Sem preço inventado: minutos e sessões aqui, dinheiro na tabela do provedor.

Como funciona

Do pedido ao registro

Um ciclo curto, repetido em cada sessão. As flags de modelo e esforço são as reais dos dois CLIs (lidas do --help): --model/--effort no Claude Code, -m/-c model_reasoning_effort no Codex.

pedido→ /qual-agente ou $qual-agente→ agente + perfil→ duplo.sh claude|codex <perfil>→ trabalho no cérebro→ duplo.sh sync→ duplo.sh uso registrar
1

Rotear

MCP específico → o agente que o tem. Código → onde o repo está aberto. Auditoria, arquitetura, wiki grande → raciocinio. Achar, resumir, redigir → rotina.

2

Abrir

duplo.sh claude raciocinio imprime e executa cd cérebro && claude --model fable --effort high. --so-mostrar só imprime.

3

Sincronizar

Editou o manual ou uma skill? sync regrava o espelho a partir do canônico (AGENTS.md, .claude/skills). Nunca apaga; avisa.

4

Registrar

Uma linha por sessão: agente, perfil, modelo, esforço, minutos, tarefa. Na quinta-feira, uso resumo diz onde a cota foi.

Guia de uso · passo a passo

Instalar, verificar, rotear, registrar

Comandos reais. Substitua ~/meu-cerebro pela pasta do seu cérebro.

1

Instalar no cérebro

Clona o repo e copia as duas skills para .claude/skills e .agents/skills, e o duplo.sh (com perfis/ e modelos/) para scripts/. Roda o verificar no final.

git clone https://github.com/inematds/cerebro-duplo.git
cd cerebro-duplo
bash instalar.sh ~/meu-cerebro
2

Verificar a paridade

Manual idêntico, skills espelhadas, openai.yaml presente, rotas do manual válidas. Código 1 se houver PROBLEMA; rota quebrada é só AVISO (o /iniciar cria vários arquivos depois).

cd ~/meu-cerebro
bash scripts/duplo.sh verificar
# OK: AGENTS.md e CLAUDE.md são idênticos
# OK: 10 skills idênticas nos dois lados
# == resultado: 0 problema(s), 6 aviso(s)
3

Ajustar os perfis ao seu plano

Os nomes de modelo que vêm no repo são os desta máquina. Edite scripts/perfis/*.env. Fontes confiáveis: claude --help (aliases fable, opus, sonnet; esforço low…max) e o seu ~/.codex/config.toml.

bash scripts/duplo.sh perfis
#   codigo       claude: fable/high     codex: gpt-6-astra/high
#   padrao       claude: sonnet/medium  codex: gpt-6-astra/medium
#   raciocinio   claude: fable/high     codex: gpt-6-astra/high
#   rotina       claude: sonnet/low     codex: gpt-6-astra/low
nano scripts/perfis/padrao.env
4

Perguntar qual agente usar

Dentro de qualquer sessão. A skill responde em quatro linhas: agente · perfil · modelo/esforço, dois motivos, o comando, e a linha de registro para o fim.

# no Claude Code
/qual-agente preciso auditar o cérebro, faz um mês que não rodo
# no Codex
$qual-agente preciso auditar o cérebro, faz um mês que não rodo

# resposta típica:
# codex · raciocinio · gpt-6-astra/high
# Auditoria é raciocínio pesado: modelo barato infla a nota.
# Codex porque o Claude Code já gastou mais cota esta semana.
# bash scripts/duplo.sh codex raciocinio
# ao fechar: bash scripts/duplo.sh uso registrar codex raciocinio 25 "auditoria mensal"
5

Abrir o agente com o perfil

O script imprime o comando antes de executar. Com --so-mostrar só imprime (bom para conferir as flags sem gastar cota).

bash scripts/duplo.sh claude raciocinio --so-mostrar
# comando: cd ~/meu-cerebro && claude --model fable --effort high --name duplo:raciocinio

bash scripts/duplo.sh codex rotina --so-mostrar
# comando: codex -C ~/meu-cerebro -m gpt-6-astra -c model_reasoning_effort=\"low\"

bash scripts/duplo.sh codex raciocinio      # abre de verdade
6

Sincronizar depois de editar

Edite sempre o canônico (AGENTS.md, .claude/skills/...). O sync regrava o outro lado. --fonte claude inverte o sentido do manual quando a edição boa está no CLAUDE.md.

bash scripts/duplo.sh sync                  # AGENTS.md → CLAUDE.md; .claude/skills → .agents/skills
bash scripts/duplo.sh sync --fonte claude   # CLAUDE.md → AGENTS.md
bash scripts/duplo.sh verificar             # 0 problema(s)
7

Registrar o uso e ler o resumo

Uma linha por sessão em registro-uso.md (criado do template na primeira vez). O resumo é o que alimenta a regra de cota: semana apertada, cai um degrau ou troca de agente.

bash scripts/duplo.sh uso registrar codex raciocinio 25 "auditoria mensal"
bash scripts/duplo.sh uso registrar claude rotina 8 "resumo reunião 06/09"
bash scripts/duplo.sh uso resumo
# | Agente | Sessões | Minutos |
# | claude | 1 | 8 |
# | codex  | 1 | 25 |
# total: 2 sessões, 33 minutos
8

Relatório de paridade pelo agente

A skill duplo-verificar roda o verificar e transforma a saída num relatório curto com um conserto por item. Não conserta sozinha: termina perguntando se pode aplicar.

/duplo-verificar       # Claude Code
$duplo-verificar       # Codex

Roadmap

O que existe e o que vem

A 1.0.0 fecha o ciclo verificar → rotear → registrar. O resto é opcional e depende de uso real.

1.0.0
Ciclo completo (feito)duplo.sh com verificar, sync, claude/codex por perfil, uso; skills qual-agente e duplo-verificar; 4 perfis; instalador; 38 testes; 6 documentos.
próximo
Hook de pre-commit prontoScript opcional que instala o verificar como pre-commit no cérebro versionado (hoje é um trecho em docs/paridade.md).
próximo
Terceiro agenteBloco DUPLO_<AGENTE>_* nos perfis e cmd_<agente> no script para qualquer runtime que leia AGENTS.md (o caminho está em docs/migracao.md).
